# 调研记录

- [默认勾选原因] -> `autoLootSelect` 被写入 `kasandri6_preferences`，因此上次开启后刷新页面仍为开启 -> 应改为独立的会话状态，并清理载入对象中的旧字段。
- [控件范围] -> 用户要求设置页也可开关自动选择 -> 使用同一会话状态同步设置页与战利品弹窗的像素开关；设置中的其他复选框继续保留像素勾选框。
- [闪烁时机] -> 用户明确要求开始约 1 秒时而不是快结束时闪烁 -> 5 秒倒计时第一次递减时为推荐卡添加一次短促边框动画；倒计时结束直接结算。
- [设置标签] -> 设置页无需重复显示倒计时长度 -> 标签仅显示“自动选择装备”，5 秒信息只放在战利品弹窗状态文案。
- [自动战斗设置] -> 当前自动战斗只能从战斗操作区启动和停止 -> 设置页增加会话级开关，并复用现有 `autoBattle` 状态与战斗循环。
- [测试调整] -> 首次运行更新后的契约测试仍要求比较逻辑位于 `autoEquipRecommendedLoot()` 内而失败 -> 比较已提取为 `getRecommendedLootChoice()` 供闪烁和结算共用，测试拆分验证推荐计算与结算职责后通过。
- [样式审阅] -> 像素滑动开关同时命中普通 `.toggle` 的勾形伪元素，且目标类会在闪烁后持续高亮 -> 为滑动开关禁用 `::after`，并移除动画填充模式，使约 1 秒闪烁后恢复原边框；减少动画模式仍保留静态目标提示。
- [本地实测] -> 旧浏览器偏好曾保存自动选择开启 -> 刷新新页面后设置页两个自动开关均为关闭；恢复 BOSS 掉落后等待 1.3 秒仍无目标类，证明旧值不会触发自动动作。
- [闪烁实测] -> 战利品开关启用后约 1 秒状态变为“4 秒后”，推荐卡获得 `autoSelectTargetPulse` 且边框闪亮；约 1.1 秒动画结束后边框恢复，5 秒总计时结束直接关闭并显示迎战选项。
- [自动战斗实测] -> 设置页开启后战斗区显示“停止自动战斗”；点击停止后设置开关同步关闭并恢复手动操作。减少动画开启时开关轨道与滑块 transition 均为 `none`。
