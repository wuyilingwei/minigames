# 调研记录

- [装备语义] -> `affixTier` 已由难度 3/6/9 决定，但界面只显示制式、精工、秘藏、神铸 -> 保留名称并追加独立强化标识，文案统一称“强化等级”，不引入随机品质概念。
- [开局顺序] -> 欢迎页按钮当前直接调用 `startGame()`，而难度 3+ 的职业与祝福禁用也在该函数内生成 -> 难度必须在 `startGame()` 之前确认，否则禁用规则可能依据旧难度计算。
- [难度弹窗] -> 普通查看模式会在当前值未变化时禁用确认按钮 -> 新冒险门禁必须允许确认当前难度，并在关闭时安全返回欢迎页。
- [跨模块测试] -> 强化标识实现后，旧难度标签测试仍硬编码“精工装备/秘藏装备/神铸装备” -> 集成阶段需将其改为新的强化等级标签，并继续覆盖累计门槛。
- [标识可读性] -> 子任务初稿把 0 级显示为“制式 · 强化无标识” -> 用户要求的是额外 `+ / ++ / +++`，因此 0 级应只显示“制式”，其余显示“精工 + / 秘藏 ++ / 神铸 +++”。
- [门禁状态] -> 新冒险模式在渲染时允许调整，但 `shiftDifficulty()` 仍只检查 `player.canAdjustPoint` -> 统一让新冒险模式可调整，避免旧运行态残留导致按钮可用却不响应。
- [浏览器验收] -> 点击“新的征途”先显示可确认当前值的难度弹窗；关闭后欢迎页仍在且无职业输出；再次确认难度 10 后才生成难度 10 职业/祝福禁用 -> 开局顺序和取消状态符合要求。
- [装备实显] -> 难度 3 首战掉落三件装备，卡片分别显示“身体 · 精工 +”与“副手 · 精工 +”；基础装备只显示“制式”，难度 10 累计标签显示 +、++、+++ -> 强化标识与难度门槛一致。
