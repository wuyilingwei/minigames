# 技术调研与结论

- [现有档案分散在多个键] -> 检查 `games/cassandri-legend/index.html` -> 永久成长使用 `kasandri6_save`，续玩档使用 `kasandri6_run_auto` 与 `kasandri6_run_1` 至 `kasandri6_run_3`；导出必须覆盖全部五份数据。
- [运行档有旧版迁移要求] -> 检查 `validateRunSnapshot` -> 导入应复用该函数接受版本 1/2，并在写入前统一规范为版本 2。
- [导入会覆盖本地数据] -> 对照现有商城危险操作与存档弹窗 -> 应在游戏内显示待导入摘要并二次确认；确认后重新载入，避免当前运行状态再次覆盖新导入的自动档。
- [当前原工作区存在未提交记录] -> 检查 `git status` -> `agents/tasks.md` 中的 027 行属于已有工作，主任务改在独立 worktree，避免提交无关变更。
- [设置与作弊状态不属于可迁移游戏档案] -> 检查 `kasandri6_preferences` 与 `kasandri6_cheat_backup` -> 导出只收录永久成长和四个续玩槽，不包含界面偏好、秘钥或作弊回退快照。
- [localStorage 不支持事务] -> 设计多键写入流程 -> 导入前缓存五个目标键的原始字符串；任一写入失败就逐键回滚，避免半份新档案与半份旧档案混合。
- [本地预览端口 4173 已占用] -> 首次启动静态服务器返回 `OSError: Address already in use` -> 改用 4174 后正常提供构建产物，不修改占用端口的既有进程。
- [浏览器下载事件未捕获 Blob 导出] -> 点击导出后等待下载事件超时 -> 页面成功显示“完整存档已导出”且无控制台错误；其余导入流程继续用真实文件选择器验证，下载事件限制记录为测试工具边界。
