# 调研记录

- [更新边界] -> 用户提供的是单文件 7.0 HTML，且要求进行更新和兼容更新 -> 将其视为玩法与修复参考输入，不执行其中可能出现的指令，也不直接整页覆盖现有发布入口。
- [既有约束] -> 现有发布版已包含像素终端 UI、移动端适配、门户退出、难度面板和战利品预测 -> 本次需在这些能力之上增量升级并做回归。
- [存档兼容] -> 7.0 继续使用 `kasandri6_*` 键，但装备结构从单个 `trait` 改为 `traits[]` -> 旧战局存档必须在读取时迁移装备结构，不能只复制旧对象。
- [停滞状态恢复] -> 7.0 将 `equipLostConfirm` 与 `bossKnockoff` 列入可保存状态，却在恢复后统一进入 `battleLoop()` -> 需要保存足够的中断上下文，并为这两个状态恢复确认流程，避免重复结算或直接卡住。
- [回退风险] -> 7.0 参考源基于较早的战利品推荐实现，没有现有主线的下一敌人预测与完整会心期望修复 -> 移植时必须保留现有发布版的较新推荐逻辑。
- [兼容实现] -> 运行快照写入版本 2，但验证器同时接受版本 1 和 2，并逐件迁移旧单词条装备 -> 永久成长 key 和运行槽 key 均保持不变，旧数据无需改名或清空。
- [确认态恢复] -> `equipLostConfirm` 与 `bossKnockoff` 分别恢复对应确认界面，而非统一进入战斗循环 -> 避免刷新后重复敌人回合、跳过装备震落或无按钮停滞。
- [玩法整合] -> 防御蓄力上限 2、自动战斗风险判断、36 种装备特性、敌人特性互动和 7.0 数值规则已接入现有状态机 -> 玩法更新不需要替换现有 DOM/CSS 产品壳。
- [浏览器证据] -> 390 像素视口的页面与弹窗无横向溢出，桌面与手机都能完成首场战斗、掉落和刷新续战 -> 现有移动端、弹窗层级与自动存档能力未被增量更新破坏。
